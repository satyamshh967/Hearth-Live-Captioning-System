## 3. Root Cause Analysis: The 12-Second Latency Spike Resolved

During Step 0 of our architectural audit, we diagnosed why traditional speech applications exhibit unacceptable 12–16 second delays:

```
[Spoken Word] ──> [Wait for Full Utterance (3-5s)] ──> [VAD Silence Wait (0.8s)] ──> [OpenMP CPU Thrashing (12.3s)] ──> [Screen] (TOTAL: 15.6s)
```

### The 8 Root Causes Identified & Fixed:

1. **Unconstrained OpenMP Thread Allocation (13x Thrashing)**: On the 32-core test host, CTranslate2 defaulted `intra_threads=0` (32 threads). Overlapping partial and final decodes spawned 64 compute threads across 32 cores, ballooning a 934 ms inference into **12,309 ms**.
   - *Fix*: Clamped `cpu_threads=4` in `configs/balanced.yaml` and `streaming_engine.py`.
2. **Whole-Utterance Decoding after VAD**: Captions previously waited until speech had completely finished.
   - *Fix*: LocalAgreement streaming policy with 250 ms rolling step feeds audio while speech is still active.
3. **Repetition Token Traps**: Short audio slices at temperature 0 can trigger infinite token loops ("warm warm warm").
   - *Fix*: Added `compression_ratio_threshold=2.4`, `no_speech_threshold=0.6`, `repetition_penalty=1.15`, and adjacent token deduplication.
4. **Float64 Hardware Timestamp Tracking**: Web browsers previously could not compute true spoken-to-screen delay.
   - *Fix*: `pcm-recorder-processor.js` prepends 8-byte Float64 little-endian epoch seconds to audio frames; `ws.py` computes true end-to-end latency.
5. **Clause-Level Machine Translation**: MT previously blocked on the entire sentence.
   - *Fix*: Fast clause segmentation translates committed word prefixes asynchronously without blocking ASR.

| **Apollo Clinic** | *"a parallel clinic"* | **Apollo Clinic** |
